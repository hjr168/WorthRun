### 3. 现有匿名身份 / HMAC / 北京时间日界线工具现状（不重做，仅记录）
经代码核对，以下能力已存在，M1 必须复用：

| 能力 | 位置 | 说明 |
|---|---|---|
| 匿名 userKey → HMAC 哈希 | `apps/api/src/userIdentity.ts` `userKeyHash(secret, userKey)` | HMAC-SHA256，存于 `userAlias.userKeyHash`、`shareRecord.userKeyHash` |
| openid 哈希 | `userIdentity.ts` `openIdHash` | 注册用户唯一键 |
| 交互用户哈希 | `apps/api/src/interactionAnalytics.ts` `interactionUserHash` | 同 HMAC 模式 |
| 通用 HMAC 工具 | `apps/api/src/feedbackAbuse.ts` `hmacDigest(secret, value)` | 可复用 |
| 北京时间日界线（核心） | `packages/shared/src/index.ts` `chinaDateOnly(now)` | `YYYY-MM-DD`，UTC+8 |
| 活动日包装 | `apps/api/src/growthAnalytics.ts` `activityDate(now)` | `new Date(chinaDateOnly + T00:00:00Z)` |
| 交互日包装 | `interactionAnalytics.ts` `interactionOccurredDate` | 同模式 |
| 反馈日包装 | `apps/api/src/feedbackMaintenance.ts` `chinaDay(now)` | 同模式 |

> M1 的 `GrowthVisitorDaily.visitorKeyHash` 必须用服务端密钥 HMAC（复用上述工具），不能做可枚举的普通 SHA-256。`activityDate` 沿用系统统一北京日界线。

## 已知工程问题（记录，供后续里程碑注意）

1. **vitest 下 prisma `groupBy` / 复杂查询结果序列化栈溢出**：prisma client 结果对象在 vitest(vite-node) 加载器下含 proxy，`JSON.stringify` 会触发 `RangeError: Maximum call stack size exceeded`。基线查询改用编译后 `node` 运行的 CLI 解决。**M1/M2 的雷达与统计服务若需在测试中断言 prisma 返回，应手工提取原始字段，或用 `$queryRaw`/纯值映射，避免直接 stringify 整行。**
2. **shared 包循环依赖**（已修复）：初版 `radar.ts` 从 `index.ts` 导入城市工具、`index.ts` 又 re-export `radar.ts`，形成循环，导致 `greaterBayAreaCityValues` 在 `toMatchObject` 深比较时栈溢出（曾使 10 个测试失败）。已通过提取无循环依赖的 `region.ts`（`index.ts` 与 `radar.ts` 都从此导入）彻底修复。全量 265 测试恢复通过。
