# WorthRun V0.5.5 提醒正式上线与运营收口计划

## Summary

V0.5.4 已完成赛事核验、提醒订阅、体验版发送和后台基础运营能力。V0.5.5
不新增个性化推荐、分享增长或赛事源，重点解决正式开启提醒前仍存在的运行配置、
数据资格和日常运维风险。

当前基线：

- 12 场未来已发布赛事均已人工核验，但只有 2 场具备真实开赛时间。
- 当前没有符合报名提醒条件的赛事；已有报名时间的赛事均已结束报名。
- 线上存在 2 条同日、同城、同距离的澳门马拉松重复赛事。
- 正式提醒开关仍关闭，微信环境仍为 `trial`，提醒 cron 尚未安装。
- PM2 进程可能继承历史环境变量，导致运行中的模板配置与 `.env` 不一致。
- UniCloud 空间当前到期时间为 2026-08-26，上线前必须续费并更新准确日期。

验收目标：

- 正式运行进程使用的提醒配置与服务器 `.env` 完全一致，不再继承 PM2 历史变量。
- 已发布赛事不存在会造成重复订阅或重复提醒的明显重复记录。
- 至少 2 场赛事可订阅赛前提醒，至少 1 场赛事可订阅报名提醒。
- 2–3 个内部微信账号在体验版完成两类模板的真实发送。
- 体验版连续观察 48 小时，无重复发送、模板错误或新增提醒相关 5xx。
- `live` 预检无阻塞项后切换正式版并安装提醒 cron。
- API 继续保持单个 PM2 进程，API RSS 小于 220MB，提醒任务 RSS 小于 120MB。

## Implementation Changes

### 1. 收口 PM2 运行环境

- 新增 `ops/start-api-clean-env.sh`，以白名单方式设置 `HOME`、`PATH` 等必要变量，
  再由 Node 从服务器 `.env` 加载运行配置。
- 修改 `ecosystem.config.cjs`，通过清洁环境启动脚本执行 API，避免 PM2 daemon
  保存的旧模板 ID、功能开关或微信环境覆盖 `.env`。
- `APP_RELEASE` 继续从发布过程显式注入；密钥、OpenID 和完整模板配置不得写入
  PM2 配置、日志或后台响应。
- 预检增加“文件配置与进程配置一致性”检查，只比较非敏感配置的哈希或布尔结果，
  不回传配置原文。
- `GET /api/admin/reminder-readiness` 增加：
  - `runtimeConfigMatched`
  - `cloudDaysRemaining`
  - `environment`
  - `featureEnabled`
  - 可直接执行的阻塞原因列表
- `live` 模式下，运行配置不一致、UniCloud 剩余不足 30 天、微信环境不是
  `formal` 或提醒开关未开启均为阻塞项。

### 2. 治理重复赛事并阻止再次发布

- 在发布检查中增加“已发布赛事疑似重复”规则：
  - 标准城市相同。
  - 比赛日期相同。
  - 距离项目有重叠。
  - 标准化名称相似，或存在相同官方来源依据。
- 疑似重复只阻止新发布，不自动合并或删除数据。
- 数据治理增加 `archive_duplicate_published_event`：
  - 必须指定主赛事与重复赛事。
  - 默认 dry-run，返回关联收藏、选择、提醒、反馈、互动和来源摘要数量。
  - apply 必须携带 dry-run 的预期数量和两条记录的 `updatedAt` 快照。
  - 重复赛事改为归档并记录主赛事 ID、原因和执行管理员，不做物理删除。
  - 存在未发送提醒或用户个性化数据时拒绝自动应用，转人工处理。
- 首次治理归档重复澳门马拉松记录，保留信息更完整、来源更可信的一条作为主赛事。
- 后台“数据质量”和“赛事核验”显示重复赛事数量及处理入口。

### 3. 补齐真实提醒数据

- 统一复用 `reminderWorkflow` 的资格判断，不在后台、小程序和预检中分别维护规则。
- 后台赛事核验列表增加：
  - 可用提醒类型。
  - 缺少真实开赛时间。
  - 缺少报名开始或截止时间。
  - 报名时间已过期。
  - 来源摘要或赛事信息需要复核。
- 增加“仅看缺少提醒时间”和“仅看可订阅赛事”筛选，点击后进入原赛事编辑页补齐。
- 所有提醒时间必须来自人工核验的官方或可信来源；禁止使用 AI 推测、
  默认 `00:00` 或仅有日期的值。
- 修改开赛、报名或来源关键字段后继续自动降级为 `pending_verify`，
  并将未发送提醒转为 `review_required`。
- 正式灰度前人工补齐并重新核验：
  - 至少 2 场真实 `eventStartAt`。
  - 至少 1 场未来有效 `signupStartAt` 或 `signupDeadline`。
  - 去重后至少 3 场赛事具备一种提醒资格。

### 4. 完成两类模板体验版实发

- 保留 `reminder:test-send` 的 trial-only 限制，正式环境禁止使用测试发送命令。
- 测试发送必须使用真实用户、真实已核验赛事和真实订阅授权，不生成虚构时间或
  绕过微信授权的测试记录。
- 测试命令执行前再次校验：
  - 用户正常且 OpenID 可用。
  - 赛事仍已发布并已核验。
  - 对应提醒时间仍有效。
  - 提醒状态为待发送且未曾发送。
  - 当前运行环境为 `trial`。
- 测试结果只输出用户、赛事和运行记录的内部 ID以及脱敏错误类别，
  不输出 OpenID、access token 或消息正文。
- 使用 2–3 个内部账号覆盖：
  - 允许订阅并收到报名提醒。
  - 允许订阅并收到赛前提醒。
  - 拒绝订阅，不创建服务端提醒。
  - 取消提醒后不发送。
- 同一用户、赛事和提醒类型测试成功后不得重置为待发送或重复测试。

### 5. 增加定时任务健康信号

- 每次 cron 执行均写入 `ReminderDeliveryRun`，即使没有到期提醒也记录成功空运行，
  作为轻量心跳；空运行仍不得请求微信 access token。
- 提醒就绪摘要增加：
  - `eligibleByType`
  - `overduePending`
  - `latestRunAt`
  - `latestRunAgeMinutes`
  - `recentFailures`
  - `healthStatus`
- 后台在以下情况显示高优先级警告：
  - 正式开关开启后超过 30 分钟没有任务运行记录。
  - 存在已过计划时间但仍为 `pending` 的提醒。
  - 最近运行出现模板、鉴权或数据库错误。
  - UniCloud 空间剩余不足 30 天。
- 新增只读 `GET /api/admin/reminder-runs`，支持分页查看近 90 天运行摘要；
  不展示 OpenID、消息正文或敏感错误详情。
- 延续现有维护任务清理 90 天前记录，不增加常驻 worker 或新维护 cron。

### 6. 正式启用与可回退发布

正式上线顺序固定为：

1. 续费 UniCloud，更新 `UNICLOUD_SPACE_EXPIRES_AT`，先运行 `ready` 预检。
2. 部署清洁 PM2 启动方式，重启后核对进程配置一致性和单进程 RSS。
3. 对澳门重复赛事执行治理 dry-run，确认无用户数据后 apply。
4. 补齐真实提醒时间并重新核验赛事。
5. 保持 `trial + feature disabled`，完成两类模板真实测试发送。
6. 连续观察 48 小时，检查提醒运行记录、5xx、微信错误和重复发送。
7. 设置 `WX_MINIPROGRAM_STATE=formal` 和 `REMINDER_FEATURE_ENABLED=true`。
8. 重启 API 后运行 `live` 预检，只有零阻塞项才安装提醒 cron。
9. 验证首次空运行心跳、到期任务处理和后台健康状态。
10. 正式上线后观察 24 小时和 7 天，记录订阅、发送、失败和授权漏斗。

回退规则：

- 立即设置 `REMINDER_FEATURE_ENABLED=false` 并移除提醒 cron。
- 重启 API 后验证用户仍可浏览赛事，但不能新建提醒。
- 不删除提醒、订阅授权或发送运行记录。
- `sent` 永久保持已发送，禁止重置重发。
- `pending` 保留，恢复上线前重新检查资格；不自动补发已经失去时效的提醒。
- 回退不修改已核验赛事和用户个人数据。

## Test Plan

- 测试 PM2 父进程存在旧变量时，API 最终仍以服务器 `.env` 为准。
- 测试配置一致性检查只返回状态，不泄露模板 ID、密钥或 OpenID。
- 测试 UniCloud 剩余不足 30 天时 `live` 预检失败。
- 测试同城、同日、距离重叠的重复发布拦截及非重复赛事不被误伤。
- 测试重复赛事治理的 dry-run、快照冲突、关联数据保护、审计日志和幂等性。
- 测试报名开始、截止前 3 天、赛前 7 天、跨北京时间日期和不足 24 小时边界。
- 测试空运行写心跳但不请求微信 access token。
- 测试网络和微信系统错误重试，模板和权限错误终止，`sent` 永不重发。
- 测试后台提醒问题筛选、运行记录分页、逾期和任务失联警告。
- 执行：
  - `pnpm test`
  - `pnpm typecheck`
  - `pnpm --filter @worth-running/api build`
  - `pnpm --filter @worth-running/admin build`
  - `pnpm exec tsc -p apps/miniapp/tsconfig.json`
- ECS 部署前备份 PostgreSQL 并记录 SHA-256。
- 检查生产后台活动资源不包含 `localhost:4000`，验证登录预检和 CORS。
- 验证 PM2 只有一个 WorthRun API 进程，API RSS 小于 220MB。
- 使用 `/usr/bin/time -v` 验证提醒任务峰值 RSS 小于 120MB。
- 检查近 7 天系统无 OOM、提醒无重复发送、无未解释的模板错误。

## Rollout Gate

以下条件必须全部满足后才能开启正式提醒：

- [ ] UniCloud 已续费，剩余有效期不少于 30 天，建议不少于 90 天。
- [ ] API 运行配置与服务器 `.env` 一致。
- [ ] 两个微信模板及字段预检通过。
- [ ] 重复澳门赛事已完成可追溯治理。
- [ ] 至少 2 场赛事可用赛前提醒。
- [ ] 至少 1 场赛事可用报名提醒。
- [ ] 2–3 个体验账号完成两类模板真实发送。
- [ ] 体验版连续 48 小时无重复发送和提醒相关新增 5xx。
- [ ] `live` 预检零阻塞。
- [ ] cron、flock、日志目录和 logrotate 验证通过。
- [ ] API 和提醒任务内存符合限制。
- [ ] 回退流程至少演练一次。

## Assumptions

- V0.5.5 只完成提醒正式上线和运营收口。
- 首页多城市、多距离、`focusTags` 个性化推迟到 V0.6。
- 分享卡和分享归因优化不纳入本版本。
- 不新增赛事源、短信、邮件、Redis、消息队列、外部监控或常驻 worker。
- 不自动核验赛事，不用 AI 推测时间，不自动订阅或自动补发。
- 正式上线前需要运营人员续费 UniCloud，并提供更新后的准确到期时间。
- 固定保留“AI 整理，仅供参考，报名以官方为准。”和“前往官方确认”。
- 不覆盖或提交现有 `apps/miniapp/pages/share-card/index.ts` 和
  `apps/miniapp/pages/share-card/index.wxss` 用户修改。
